# 日本民話データベース：調査中（researching）管理・現地調査ワークフロー

## 1. 目的

日本民話データベースにおける `researching` を単なる未完成状態ではなく、AI調査・図書館調査・郷土資料調査・現地調査を継続するための「調査案件」として管理する。

公開Web上で本文まで確認できない民話も、タイトル、地域、出典、確認可能性のある場所などを先に構造化して蓄積する。

これにより、AIによるオンライン調査と人間による現地調査を連携させる。

---

## 2. 基本方針

### 2.1 調査不能を理由に収集を止めない

資料本文が確認できない場合でも、確認済みのメタデータを登録候補として残す。

最低限、可能な範囲で以下を保存する。

- タイトル
- 別題・異称
- 都道府県
- 市区町村
- 詳細地域
- 主体（人物・動物・妖怪・神仏など）
- 出典
- 原資料URLまたは目録URL
- 現時点で不足している情報
- 今後確認できそうな場所

本文が確認できないこと自体をデータ損失とせず、後続調査のためのリードとして扱う。

### 2.2 `researching` は横断的に閲覧できるようにする

`research_status: researching` の民話は、通常の民話一覧とは別に「調査中の民話」として横断一覧できるようにする。

主な絞り込み軸は以下とする。

- 都道府県
- 市区町村
- 詳細地域
- 主体・存在
- 横断タグ
- 伝承群
- 不足情報
- 調査優先度
- 確認候補施設

例：

> 市川市へ行く → 市川市 × researching を表示 → 図書館や現地で確認すべき民話を一覧化

---

## 3. 研究ステータス

個別民話は以下の状態を持てるようにする。

- `researching`：資料本文または重要情報の確認待ち
- `partial`：一部資料・一部内容を確認済み
- `reviewed`：必要情報を確認し整理済み
- `published`：公開済み

必要に応じて、WordPressの公開状態とは別に研究ステータスを保持する。

### 3.1 `researching` の意味

以下のような場合に使用する。

- 本文未確認
- 詳細なあらすじ未確認
- 正確な伝承地未確認
- 出典資料の所蔵場所未確認
- 同一話か異伝か未判定
- 同一人物・同一存在か未確定

`researching` は「不採用」ではなく、継続調査対象を意味する。

---

## 4. 調査情報モデル

個別民話に、必要に応じて以下の構造を持たせる。

```json
{
  "research_status": "researching",
  "research_priority": "normal",
  "research_missing": [
    "story_content",
    "exact_location",
    "source_text"
  ],
  "research_notes": "資料目録上でタイトル・地域・出典のみ確認。本文未確認。",
  "research_leads": [
    "library",
    "local_archive",
    "local_site"
  ]
}
```

### 4.1 `research_priority`

- `high`：現地・資料確認によって重要な情報が得られる可能性が高い
- `normal`：通常の継続調査対象
- `low`：現時点では情報が少なく、後回し可能

### 4.2 `research_missing`

例：

- `story_content`
- `summary`
- `exact_location`
- `source_text`
- `source_availability`
- `subject_identity`
- `variant_relationship`

---

## 5. 出典と確認場所を分離する

出典情報と、実際に確認・閲覧できる場所は別構造で管理する。

### 5.1 `sources`

資料そのものの書誌情報を保存する。

- 資料名
- 編者・著者
- 発行者・提供機関
- 発行年
- URL
- 利用条件
- 参照日
- AIが確認できた範囲

### 5.2 `verification_locations`

資料または伝承を確認できる可能性のある場所を保存する。

例：

```json
{
  "verification_locations": [
    {
      "type": "library",
      "name": "市川市立図書館",
      "reason": "郷土資料・収録資料の所蔵確認候補"
    },
    {
      "type": "library",
      "name": "千葉県立中央図書館",
      "reason": "県域資料の所蔵確認候補"
    },
    {
      "type": "local_site",
      "name": "関連寺社・伝承地",
      "reason": "現地伝承・碑・地域資料の確認候補"
    }
  ]
}
```

### 5.3 確認場所の種別

- `library`
- `local_archive`
- `museum`
- `temple`
- `shrine`
- `local_site`
- `municipal_office`
- `historical_society`
- `other`

## 6. 現地調査候補

AI調査で現地確認の価値があると判断した場合、以下を保存する。

```json
{
  "field_research": {
    "visit_candidate": true,
    "priority": "normal",
    "places": [
      "確認候補施設または伝承地"
    ],
    "local_leads": [
      "地域名",
      "寺社名",
      "川・山・旧村名など"
    ]
  }
}
```

これにより、将来的に次のような検索を可能にする。

- 今度、市川市へ行くので調査中案件を出す
- 千葉県内で図書館確認が必要な民話を出す
- 寺社の現地確認候補を出す
- 狐狸貉タグの調査中民話だけ出す

## 7. AIと人間の共同調査フロー

```text
公開Web・デジタルアーカイブ
↓
AIが候補を発見
↓
タイトル・地域・出典・主体を構造化
↓
本文確認可？
├─ Yes → 内容を要約・整理
└─ No  → researchingとして登録
             ↓
      不足情報を明示
             ↓
      所蔵・確認候補を探索
             ↓
      図書館・郷土資料館・現地調査候補として蓄積
             ↓
      人間が確認・追記
             ↓
      partial / reviewedへ更新
             ↓
      必要に応じて公開
```

## 8. 調査中一覧ページ

将来的にWordPress上で以下の一覧を提供する。

# 調査中の民話

表示項目例：

- 民話タイトル
- 都道府県・市区町村
- 詳細地域
- 主体・存在
- 横断タグ
- 伝承群
- 不足情報
- 出典
- 確認候補
- 調査優先度

この一覧は、単なる未完成記事一覧ではなく「次に何を調べるか」を管理する研究インターフェースとする。

## 9. 地域 × 主体ルールとの接続

既存の「地域 × 主体」伝承群ルールと `researching` を組み合わせる。

例えば、同じ地域の狐伝承を複数確認したが本文未確認の場合でも、個別民話を消さずに以下のように管理する。

```text
行徳・狐伝承群
├─ 民話A（researching）
├─ 民話B（partial）
└─ 民話C（researching）
```

また、全国横断タグからも確認できる。

```text
狐狸貉
├─ 狐
├─ 狸
└─ 貉（ムジナ）
```

地域伝承としては混在させず、横断タグによって全国比較を可能にする。

---

## 10. 最低登録ルール

本文未確認の民話でも、以下の6項目を可能な限り保存する。

1. タイトル
2. 地域
3. 出典
4. 確認可能な場所または所蔵候補
5. 現地確認候補
6. 不足している情報

これにより、AIだけでは確認できない資料を後から人間が補完できる構造を維持する。

---

## 11. 運用原則

- 資料が読めないことを理由に調査全体を停止しない
- 確認できた事実と推測を明確に分ける
- 出典と確認候補を混同しない
- `researching` を積極的に蓄積する
- 人間の現地調査で追記できる構造を優先する
- 後から同一話・異伝・伝承群の関係を更新できるようにする

この仕組みにより、日本民話データベースを「AIが自動収集して完成するデータベース」ではなく、AIと人間の調査を継続的に積み上げるデータベースとして運用する。
